# Historical Data Pipeline

This directory stores market data used for historical analysis and backtesting.

## Raw data

- Raw files live in `data/raw/`.
- These files are source data snapshots and should not be edited manually.
- Raw data may include malformed rows, duplicates, and timezone/format inconsistencies.

## Processed data

- Cleaned data lives in `data/processed/`.
- Processed files are the canonical data used by backtesting code.
- They are generated by the Python cleaning pipeline and should be treated as derived artifacts.

## Expected CSV format

Each row should represent one OHLCV candle with the following columns:

- `timestamp`
- `open`
- `high`
- `low`
- `close`
- `volume`

Example:

```csv
timestamp,open,high,low,close,volume
2024-01-01 00:00:00+00:00,100.0,101.0,99.5,100.5,1234.0
```

## Timestamp convention

- Timestamps must be timezone-aware or converted to UTC before storage.
- The pipeline converts timestamps to UTC and sorts them ascending.
- Data should not contain duplicate timestamps.

## OHLCV rules

The data must satisfy:

- `open > 0`
- `high > 0`
- `low > 0`
- `close > 0`
- `volume >= 0`
- `high >= max(open, close)`
- `low <= min(open, close)`

## Why raw data is preserved

Raw files act as the original, unmodified market history. This makes it possible to replay data cleaning rules and audit any transformation applied later.

## Real data source expectation

This repository currently includes a tiny sample file under `python/data/raw/` and a sample cleaned file under `python/data/processed/`. Those files are only examples for the schema and pipeline contract. For meaningful walk-forward research, a genuinely large BTCUSDT 1h historical export must be supplied from a real exchange or market-data provider (for example, Binance historical candles exported as OHLCV CSV).

The expected source is a real BTCUSDT 1h OHLCV export. The pipeline will only accept that data if it is large enough and passes the validation rules below.

## Why cleaned data is used for backtesting

Backtesting should use cleaned, validated candles only. The cleaned dataset is sorted, deduplicated, and checked for missing intervals and invalid OHLCV values so that downstream analysis is based on consistent data.
